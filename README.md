## 官方渠道长什么样

Claude API 是一套 RESTful 接口，用来程序化调用 Claude 的各个模型。走官方路线的前提有两个：一个 Claude Console 账号，一把 API key。

常用的接口就几类：

- **Messages API**：对话和生成的主接口，日常调用基本都走这里
- **Message Batches API**：把大批请求异步丢过去处理，成本直接砍半
- **Token Counting API**：发送之前先数一遍 token，用来估成本、防超限
- **Models API**：查询当前可用的模型列表

Beta 阶段还有 Files、Skills、Agents、Sessions 这些接口，主要面向做智能体的团队，普通调用暂时用不上。

认证靠请求头里的 `x-api-key` 和 `anthropic-version`。用官方 SDK 的话，这些头会自动处理，不用手动拼。如果团队里有多个项目共用额度，Console 里的 workspaces 可以把 key 按用途拆开管理，方便分别控费。

计费按 token 用量来，限流则按 tier 分级：每个层级有月度消费上限，外加每分钟请求数（RPM）和每分钟 token 数（TPM）两道闸。层级会随用量自动提升，也可以在 Console 里主动申请提额。

还有一个容易忽略的点：官方 API 并不在所有国家和地区开放，注册前最好先确认自己所在区域是否在支持列表里。

**限流和封禁。** 官方账号存在 waitlist、限速、暂停使用的情况。正在赶项目的时候突然被限流，比贵一点更让人难受。

## 常见问题

**代充的 key 和官方 key 用起来有区别吗？**

调用方式上没有区别，官方 SDK 换个 base_url 就能跑。区别在计费和账户体系：余额在平台，限流规则由平台定。

**代充会不会把账号搞出问题？**

官方的限流和暂停机制针对的是账号和通道。选走官方上游、合规转发的平台，风险可控，但没有任何平台能承诺零风险，这点要有预期。

可以。配合 CC Switch 这类切换工具，把中转平台的 key 配置进去，Claude Code 以及 OpenClaw、OpenCode 等编码工具都能用同一把 key。
